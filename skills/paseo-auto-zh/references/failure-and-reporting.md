# 失败与上报纪律

**什么时候读**：Paseo daemon 不可用、MCP 工具缺失、`create_agent` 回执异常、权限请求无法
自动处理、通知停摆、熔断触发，或需要向用户上报时。

## 9. 失败与上报纪律

- **控制面不可用**：MCP 工具不在，且 `paseo status --json` 报 daemon 异常时，报告精确错误
  （命令、退出码、错误文本）并停止。不要猜命令、不要换可执行文件、不要无条件重启 daemon。
  需要本地证据时读 `~/.paseo/daemon.log` 的最近条目；重启只在用户要求或明确是本地 daemon
  操作时进行，且重启后重新核对 agent 状态再继续。
- **MCP 派活失败**：按 [agent 恢复](agent-recovery.md) 取证后决定重试或报告。
  **不要**为了绕过失败退回到 CLI 异步派活——CLI 不武装完成通知，会静默失去唤醒。
  确实只能用 CLI 时，切到有界等待档并明确告知用户。
- **通知停摆**：agent 已 idle 但没有通知时，先读 `get_agent_status` / `get_agent_activity`
  与 workspace 证据；工作已完成就继续验收，不要求重发。agent 仍在跑就不要打扰。
- **权限请求无法自动处理**：涉及凭证、第三方账号、付费、人工审批、不可逆 live 数据操作时，
  立即停下问人，说明请求的操作、目标与风险。不自动批准，不切 bypass 模式。
- **任何环节触发熔断**（单票：连续 2 次过不了同一门禁；run 级：累计打回阈值）→ 立即停下
  问人，说明卡在哪个阶段、已有的证据、需要人决定什么。
- **agent 被关闭 / 取消 / 报错**：按 [agent 恢复](agent-recovery.md) 处理；先确认已提交工作
  是否持久化，再决定替代还是打回。无证据从不授权删除 workspace 或 force-push。
- **流程错误**（可能复发的 harness 缺陷）到安全点后做只读 retro，候选单交人选定后才落地，
  见 [长程票图](long-horizon-tickets.md) §6。retro 不在运行中途修改 skill。
- 已获授权的实施工作不因任务小或 repo 缺 `WORK_SCOPE` 而跳过派活；纯问答、报告及超出
  本轮交付终点的后续阶段不派活。范围不明时先只读探索并按 §1 复核。
- 后续阶段已在本轮范围内时直接推进；不在范围内时在报告写明状态与下一步入口。
- 设计术语遵循仓库语言；需要架构分析时使用 codebase-design 的词汇帮助表达。

## 上报格式

报告应能独立理解，至少包含：

```text
本轮请求与交付终点
卡在哪一步（通道 / 派活 / 验收 / 合并）
精确错误与证据位置（命令、退出码、日志、agentId、workspaceId、PR）
已尝试的恢复动作与结果
仍在运行的 agent / 待处理项
需要人决定什么（若有）
```

不要把「通知没来」写成「worker 失败」，也不要把「PR 已开」写成「工作已完成」。
