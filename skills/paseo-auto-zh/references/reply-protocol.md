# 应答协议：决策问人，细节代答

**什么时候读**：收到 worker 通知、判断它是在提问还是已完成时；或判断该升级问人还是代答时。

worker（grill / wayfinder / prototype 等）的每个提问，先分类再决定谁来答。
本 skill 的核心是让流程不因提问停摆——但「不问人」不是默认值。
已授权项目改动的 PR 合并属于 §6 的执行步骤，不是需要重新请示的产品决策；
只有合并会改变用户指定范围或需要额外外部授权时，才按本节升级。
worker 的 `recommended:` 只是参考信息：**任何提问都不允许不经分类直接把推荐当答案。**

## 5.1 识别提问

通知正文的 `<agent-response>` 里：

- 以 `[[PASEO-ASK]]` 开始、`[[/PASEO-ASK]]` 结束 ⇒ 提问；
- 以 `[[PASEO-DONE]]` 结束 ⇒ 完成报告，走 §6 验收；
- 两者都没有，但 agent 已 idle ⇒ 视为「回合结束但未按契约收尾」；读活动与 workspace，
  按 [通知与等待](notifications-and-waiting.md) §5 发一次补收尾指令，不直接验收。

截断的响应先用 `get_agent_activity({agentId})` 读全文，再分类。
一次通知里可能既有实现进展又有提问；以最后的契约块为准。

## 5.2 分类判据（逐条对照；满足任一即决策类）

1. **影响交付物形态或用户可观察的行为**：产品方向、需求取舍、UI / 文案 / 交互的可见取舍。
2. **方案分叉**：多个可行实现路径，选型影响架构、依赖、seam 或后续票的划分。
3. **scope 边界**：某功能做不做、Out of Scope 放什么、验收标准宽严。
4. **escalation 五类**：凭证、第三方账号、付费、人工审批、不可逆 live 数据操作——
   这类跳过其余判据，立即停下，把问题原样转给人类，等人工答复再继续。宁可多停，不可代答。
   **「停」的是这条 worker，不是整个 run**：多票并行时，escalation 冻结出事的那张票，
   其余票照常推进门禁——一张票的凭证问题不该冻结整条流水线。全局冻结只发生在 §6
   打回协议的 run 级熔断触发时。

四条都不沾——只涉及命名、目录位置、实现手法、测试写法、库内 API 用法等——才是**细节类**，
由你代答（§5.4）。自检：写不出「它为什么不沾这四条」，就当决策类处理——理由写不出，分类就不成立。

**前提矛盾**：若提问暴露出与仓库事实、`CONTEXT.md`、ADR 或本票 spec 矛盾的前提
（例如「本仓没有登录功能」却有人在改登录页），不要按细节硬答，也不要直接继续实施；
按判据 3（scope 边界）升级给人，并附上只读证据，请人确认是「票挂错仓库 / 越界」还是「前提已变化」。

注意方向：旧版把「需求不清楚 / 拿不准用户想要哪个方案」列为永不问人、必须自裁；
**现在这类恰恰是判据 1 / 2 覆盖的决策类，必须问人。**

## 5.3 决策类：附倾向请人定夺

暂停回复 worker，先把三样东西摆给人：

- worker 的原问题（含它给的推荐与理由，若有）；
- 你的倾向与一句理由（依据项目上下文 / ADR / spec / 用户原话）；
- 其余选项的一句话代价。

人确认或改选后，才用 `send_agent_prompt` 回复 worker。人的选择与你不同时以人为准，
不二次游说；确有强烈技术理由可以说一次，人不改就按人的走。一次把问题说清，减少来回。

## 5.4 细节类：coordinator 代答

用项目上下文、ADR、spec、用户原话做依据，选最贴近用户已表达意图与现有架构的选项；
worker 的推荐与依据不冲突时照推荐答，冲突时在应答里说明为何弃推荐。理由写进应答。

应答模板：

```text
[[PASEO-ANSWER]]
decision: <结论>
basis: <依据：spec / ADR / 用户原话 / 仓库约定>
next: <要求 worker 继续做什么；不要重复整份 spec>
[[/PASEO-ANSWER]]
```

`send_agent_prompt` 默认 `steer`；worker 此刻已 idle，会直接开始新 turn。
不要为了「重新武装通知」额外发一条空消息——这次回答本身已经重新武装。

## 5.5 记录

在台账（或 Answer 的 Decisions 小节）追加 `Q → A（人定 / 代答）→ 一句理由`；
问人的把人的选项要点也记下。§7 报告汇总这份审计清单，人可事后推翻任何一条代答。

## 5.6 权限请求不是提问

通知正文含 `<permission-request>` 时，按 [agent 恢复](agent-recovery.md) 的权限一节处理：
只批准本轮已授权的操作；涉及凭证、第三方、付费、审批或不可逆操作时按 §5.3 升级。
不得把「允许」当成默认，也不为了消掉提示而切到 bypass 模式。
